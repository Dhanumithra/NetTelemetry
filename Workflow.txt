NetTelemetry
Computer Networks Implementation Plan, System Workflow & Two-Member Work Distribution
1. Project Identity
NetTelemetry is primarily a Computer Networks project. Its core purpose is to observe network communication and performance. Python, database storage, analytics and Streamlit are supporting technologies. The central flow is network communication → measurement → telemetry → network-performance analysis → anomaly identification → visualization.
2. Core Networking Problem
A network can be technically connected while providing poor communication quality. A destination may respond slowly, lose packets intermittently, show unstable delay or provide reduced throughput. NetTelemetry continuously observes these characteristics so performance degradation can be identified from measured network behaviour.

4. Complete Network Workflow
1. Configure permitted IP addresses/hostnames, probe interval, timeout and optional TCP/UDP ports.
2. Resolve hostnames when necessary and retain the resolved address for the observation.
3. Send an ICMP Echo Request or perform a configured TCP/UDP test.
4. The probe travels through the network path toward the destination and the response returns where applicable.
5. Record the response or timeout, response time, status and available TTL information.
6. Calculate RTT for successful ICMP observations.
7. Calculate packet loss and availability over a measurement window.
8. Calculate jitter from consecutive successful RTT observations.
9. Run controlled TCP/UDP tests when enabled.
10. Measure throughput only with a controlled transfer/test endpoint.
11. Store timestamp, target, protocol, status, RTT, TTL, loss/jitter and other fields.
12. Calculate rolling statistics and P95/P99 latency.
13. Compare observations with the normal baseline and flag anomalies.
14. Display current status, historical performance and anomaly events.
15. Validate the system using controlled or replayable abnormal network conditions.
5. ICMP Measurement — Core CN Module
ICMP is the primary protocol for the core monitoring module. The collector sends an Echo Request; a reachable destination normally returns an Echo Reply. The elapsed time gives RTT. Repeated probes expose delay variation and packet loss. A timeout creates a failed observation. TTL can provide additional packet-level information when exposed by the operating system or measurement library.
Echo Request → network path → destination → Echo Reply → return path
Successful reply → RTT recorded
No reply before timeout → failed probe
Repeated failures → packet-loss percentage increases
Changing RTT values → jitter can be derived
TTL, when available → additional packet-level observation
6. TCP/UDP Extension — Transport Layer
After the ICMP module is stable, controlled transport-layer tests can strengthen the CN coverage. TCP can test connectivity to an explicitly configured service port and measure connection/response timing. UDP can use a controlled sender/receiver pair to observe delivery and timing. These tests must use authorized lab endpoints and are not intended for arbitrary Internet scanning.

18. Important CN Limitations for Viva
ICMP RTT is not application response time.
ICMP may be blocked or rate-limited; timeout does not always prove the whole path is down.
Ping does not directly measure throughput.
TTL depends on implementation/path and is not a complete topology map.
Probe packet loss represents the observation made by that probe, not necessarily every application.
TCP/UDP tests must use authorized endpoints.
An anomaly means unusual measured behaviour; it does not automatically identify the root cause.
19. How to Defend the CN Focus
If asked whether this is only a data-analytics project, explain: “The data is generated directly from network communication. We measure ICMP/TCP/UDP behaviour, observe packet responses and timeouts, calculate RTT, packet loss, jitter, TTL, availability and throughput, and detect abnormal network conditions. The database, Python analytics and dashboard are supporting components used to process and present network telemetry.”
